3. Nivel 1: Seguridad y Hardening (Prioridad Crítica)

Estos ajustes deben implementarse antes de abrir el servidor a conexiones externas de Internet:

1. Secretos y Contraseñas por Defecto en Texto Plano
Crítico

Diagnóstico: El archivo docker-compose.yml incluye valores de desarrollo hardcodeados (JWT_SECRET: super-secret-jwt-token-key-2026-sirh-contagestion y POSTGRES_PASSWORD: postgres).

Solución para Producción: Mover todos los secretos a un archivo .env.production no versionado y generar una clave JWT aleatoria de 256 bits:

# Generar secreto criptográfico seguro en la terminal:
openssl rand -hex 32

# En .env.production:
JWT_SECRET=c8f1e29a4d8b7c3e5f1029384756abcdef1234567890abcdef1234567890abcd
POSTGRES_PASSWORD=ContraseñaCompletaGenerada2026!#
DATABASE_URL=postgres://contagestion_app:ContraseñaCompletaGenerada2026!#@contagestion-db:5432/contagestion_db
2. Restricción de Origen en CORS (Cross-Origin Resource Sharing)
Crítico

Diagnóstico: En postgres-migration/api-contagestion/src/index.js se utiliza origin: '*', permitiendo solicitudes desde cualquier dominio web.

Solución para Producción: Limitar el acceso exclusivamente al dominio o subdominio institucional de la firma contable:

app.use(
  cors({
    origin: process.env.ALLOWED_ORIGIN || 'https://contagestion.tudominio.hn',
    methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE', 'OPTIONS'],
    exposedHeaders: ['Content-Range', 'Range-Unit', 'Content-Length', 'ETag'],
    credentials: true,
  })
);
3. Conexión de Base de Datos como Superusuario (Bypass de RLS)
Crítico

Diagnóstico: La API Node.js se conecta con el usuario postgres. En PostgreSQL, el superusuario y dueño de tablas omite por defecto las políticas de Row Level Security (RLS).

Solución para Producción: Forzar la aplicación estricta de RLS en todas las tablas sensibles:

ALTER TABLE clients FORCE ROW LEVEL SECURITY;
ALTER TABLE files FORCE ROW LEVEL SECURITY;
ALTER TABLE deadline_tasks FORCE ROW LEVEL SECURITY;
ALTER TABLE collections FORCE ROW LEVEL SECURITY;
4. Protección contra Ataques de Fuerza Bruta (Rate Limiting)
Crítico

Diagnóstico: El endpoint de inicio de sesión no limita la cantidad de intentos fallidos permitidos por minuto.

Solución para Producción: Integrar express-rate-limit en la ruta /auth/v1/token:

import rateLimit from 'express-rate-limit';

const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutos
  max: 5, // Máximo 5 intentos fallidos
  standardHeaders: true,
  legacyHeaders: false,
  message: { error: 'Demasiados intentos fallidos. Bloqueado temporalmente por 15 minutos.' }
});

app.use('/auth/v1/token', loginLimiter);
app.use('/auth/login', loginLimiter);
5. Validación de Tipos de Archivo en la Bóveda de Documentos
Crítico

Diagnóstico: En storage.js, la carga de archivos no valida la extensión ni el tipo MIME real mediante lista blanca.

Solución para Producción: Configurar un filtro estricto en Multer para admitir únicamente formatos probatorios fiscales válidos:

const fileFilter = (req, file, cb) => {
  const allowedMimes = ['application/pdf', 'image/jpeg', 'image/png', 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet'];
  if (allowedMimes.includes(file.mimetype)) {
    cb(null, true);
  } else {
    cb(new Error('Tipo de archivo no permitido. Solo se aceptan PDFs, imágenes y hojas Excel.'), false);
  }
};

4. Nivel 2: Infraestructura y Resiliencia (DevOps)

1. Conexión Cifrada Obligatoria (HTTPS / Certificados SSL)
Prioridad Alta

El sistema se ejecuta actualmente en HTTP plano. En producción es imperativo añadir un proxy inverso (Nginx, Traefik o Cloudflare) con certificados gratuitos emitidos por Let's Encrypt para cifrar todo el tráfico tributario y las contraseñas en tránsito.

2. Estrategia y Script de Respaldo Automatizado (Backups de BD)
Prioridad Alta

Los datos tributarios residen en el volumen Docker contagestion_pgdata. Debe configurarse una tarea programada diaria con cron que realice un dump comprimido y lo transmita a un almacenamiento externo (AWS S3, Google Drive o Backblaze B2):

# Tarea Cron en el servidor (todos los días a las 02:00 AM):
0 2 * * * docker exec contagestion-db pg_dump -U postgres -d contagestion_db -Fc | gzip > /backups/contagestion_$(date +\%F).dump.gz
3. Rotación de Logs de Docker y Políticas de Reinicio
Prioridad Alta

Para evitar que los archivos de registro de los contenedores consuman el disco duro con el paso de los meses, configure la rotación en docker-compose.yml:

logging:
  driver: "json-file"
  options:
    max-size: "20m"
    max-file: "5"
